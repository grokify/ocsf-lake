# Release Notes v0.2.0

**Release Date:** October 13, 2026

## Overview

v0.2.0 rebuilds ocsf-lake on top of
[ocsf-schema-go](https://github.com/grokify/ocsf-schema-go) and adds end-to-end
record-integrity support and the `ocsflake` CLI.

The lake is now strictly the datastore/application layer. The OCSF standard itself —
generated event and object structs, classification constants, caption maps, the
class-UID registry, schema validation, and `record_integrity` cryptography — is imported
from ocsf-schema-go rather than re-implemented here.

## Installation

### Library

```bash
go get github.com/grokify/ocsf-lake@v0.2.0
```

### CLI

```bash
go install github.com/grokify/ocsf-lake/cmd/ocsflake@v0.2.0
```

Building requires CGO (`mattn/go-sqlite3`).

## Highlights

- Types, constants, and validation come from `ocsf-schema-go` v0.1.0
- Verify-on-ingest and attest-on-ingest, with tamper-evident chaining
- Five integrity check modes with persisted, resumable reports
- New `ocsflake` CLI

## Breaking Changes

### `pkg/ocsf`

`ocsf.Event`, `ocsf.ParseEvent`, and the classification and metadata constants are
removed. Use the generated packages instead:

```go
import (
    "github.com/grokify/ocsf-schema-go/ocsf/events"
    "github.com/grokify/ocsf-schema-go/ocsf/objects"
)
```

`ocsf.StoredEvent` remains, gaining `Decode()`, `IntegrityStatus`, and
`IntegrityCheckedAt`.

### `pkg/validator`

The JSON Schema validator, `validator.Options`, `validator.DefaultOptions`, and the
`ErrMissing*` sentinel errors are removed. `OCSFValidator` validates against the
embedded compiled schema:

- `ModeStrict` rejects any schema violation: missing required attributes, wrong types,
  invalid enum values, constraint violations, or inconsistent classification UIDs
- `ModePermissive` rejects only malformed JSON, a missing `class_uid`, or an unknown
  event class
- `ModeDisabled` skips validation

Events that previously passed the JSON Schema validator may be rejected under
`ModeStrict` because the semantic validator is stricter.

### `Storage` interface

`Storage` gains `SetEventIntegrity`, `SaveIntegrityReport`, and `ListIntegrityReports`.
Custom implementations must add them. Ent-backed databases need a migration for the new
`integrity_status` / `integrity_checked_at` columns and the `integrity_checks` table.

### Dependencies

`github.com/santhosh-tekuri/jsonschema/v6` is no longer used.

## Features

### Typed ingest and decode

`IngestTyped` accepts generated event structs; `StoredEvent.Decode()` returns the
concrete type for a stored payload via the class-UID registry.

### Record integrity

- **Verify-on-ingest:** `IngestIntegrityMonitor` verifies producer attestations and
  stamps `integrity_status` without rejecting; `IngestIntegrityEnforce` rejects events
  that fail the policy
- **Attest-on-ingest:** the lake signs each event with its own attestation, optionally
  chaining events via `prev_event`
- **Checks:** on-demand, full, incremental, sample, and chain modes. Unsigned events
  are warnings under `Policy.AllowUnsigned=true` (default) and failures otherwise
- **Reports:** check runs persist as `IntegrityCheck` records with incremental
  checkpoints, and events can be queried by `integrity_status`

Ingest-time verification runs before the lake's own attestation is added.

### Ingest options

- Raw-data retention keeps the original bytes as received, before attestation
- Unknown-attribute policy is configurable through lake options and the CLI
- Batch ingest errors report the position of the failing event
- `Close` is idempotent and safe for concurrent use

### `ocsflake` CLI

| Command | Purpose |
|---------|---------|
| `ingest`, `get`, `query`, `count` | Load and read events (query supports `--integrity-status`) |
| `check event\|all\|incremental\|sample\|chain\|reports` | Run and review integrity checks |
| `sign`, `verify` | Sign and verify event files |
| `seed` | Generate deterministic schema-valid test data |

Command data is written to stdout and status text to stderr, so output can be piped.

### Seed generator (`pkg/seed`)

Deterministic, schema-valid test events in signed, tampered, and chained mixes. Signing
authorities are generated at runtime; no key material is committed.

## Known Limitations

- The attest-on-ingest chain tail is process-local; after a restart the chain starts a
  new segment unless `InitialChainTail` seeds it
- `metadata.uid` and attestation `chain_uid` are not yet indexed columns, so chain
  checks scan payloads
- Batch ingest aborts on the first error rather than returning per-event results

See `docs/specs/ROADMAP.md` (Phase 5) for planned work.
